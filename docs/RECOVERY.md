# 읽기 실패와 내용 누락을 구분하는 복구 판단

[한국어](RECOVERY.md) | [English](RECOVERY.en.md)

로드 지연은 저장 실패의 증거가 아니다. 반대로 저장 버튼 처리만으로 값이 보존됐다고 판단할 수도 없다.
이 예제는 확인하지 못한 상태와 확인한 불일치를 구분하고, 같은 대상의 누락 필드만 복구 대상으로 반환한다.

`src/recovery_plan.py`는 외부 사이트 접근이나 쓰기 없이 가상 관측값으로 판단을 재현한다.

| 관측 | 판단 | 다음 단계 |
|---|---|---|
| 대상 불일치 | BLOCKED_TARGET | 다른 대상에 쓰지 않음 |
| 읽기 실패 또는 오래된 관측 | RETRY_READ / UNVERIFIED | 제한된 재조회, 쓰기 금지 |
| 새 관측에서 일부 값 불일치 | REPAIR_FIELDS | 해당 필드만 복구 계획 |
| 복구 후에도 불일치 | INCOMPLETE | 완료로 표시하지 않음 |
| 새 관측에서 전체 값 일치 | VERIFIED | 가상 계약 대조 완료 |

실제 어댑터는 대상 바인딩, 저장 후 새 관측, 작업별 재시도 횟수를 제공해야 한다.
이 함수는 그 입력의 진위를 인증하지 않는다. VERIFIED는 내용의 의미적 정확성이나 최종 제출 성공도 뜻하지 않는다.
복구 실행·저장·브라우저 재열람은 이 공개 예제에 포함되지 않는다.
실패 작업의 상태는 보존하고 다른 작업은 독립적으로 판정할 수 있다.

검증: `python -m unittest discover -s tests -v`
실사이트 성공이나 처리시간 절감 수치를 이 가상 테스트의 성과로 주장하지 않는다.
